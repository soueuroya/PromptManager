Before modifying the project:

## Repository Layout Note

The repository root contains documentation and PromptManager workspace files.
The VS Code extension project itself is nested under `prompt-manager/`.

Run build, lint, compile, test, and VSIX packaging commands from:

```txt
prompt-manager/
```

## Core Development Rules

### Keep Layers Separated

Business logic:

```txt
prompt-manager/src/state/PromptManagerState.ts
```

VS Code APIs:

```txt
prompt-manager/src/ui/PromptManagerViewProvider.ts
```

UI rendering:

```txt
prompt-manager/src/ui/PromptManagerHtmlRenderer.ts
```

Shared models:

```txt
prompt-manager/src/models.ts
```

## Common Task Patterns

### Adding a New UI Feature

Usually requires updates in:

- `prompt-manager/src/ui/PromptManagerHtmlRenderer.ts`
- `prompt-manager/src/ui/PromptManagerViewProvider.ts`
- `prompt-manager/src/state/PromptManagerState.ts`

Typical flow:

```txt
Button/UI
 |
 v
postMessage()
 |
 v
Provider handler
 |
 v
State method
 |
 v
save()
 |
 v
refresh()
```

### Adding New Data

Usually requires updates in:

- `prompt-manager/src/models.ts`
- `prompt-manager/src/state/PromptManagerState.ts`
- `prompt-manager/src/ui/PromptManagerHtmlRenderer.ts`
- `prompt-manager/src/ui/PromptManagerViewProvider.ts` if persistence import/export needs to change

Also verify:

- Persistence compatibility
- Snapshot serialization
- Queue payload compatibility
- `.promptmanager/tasks.json` compatibility
- `.promptmanager/queue.json` compatibility

### Updating Queue Behavior

Update:

- `buildTaskPayload()`
- `buildPromptPayload()`

Inside:

```txt
prompt-manager/src/state/PromptManagerState.ts
```

Queue payloads should remain:

- Structured
- Explicit
- AI-readable
- Implementation-focused
- Validation-focused
- State-update parseable

Every payload generated by `buildTaskPayload()` or `buildPromptPayload()` must
end with `PROMPTMANAGER_STATE_UPDATE_BLOCK`. Keep this block easy to parse and
include:

```txt
TASK_STATUS:
PROMPT_STATUS:
QUEUE_STATUS:
ACCEPTANCE_CRITERIA:
- [index] PASS | FAIL | UNKNOWN — explanation
NEXT_QUEUE_ACTION:
AUTO_NEXT_ALLOWED:
```

Allowed values:

- `TASK_STATUS`: `TODO`, `IMPLEMENTED`, `VALIDATING`, `DONE`, `IN_PROGRESS`, `FAILED`, `BLOCKED`
- `PROMPT_STATUS`: `TODO`, `IMPLEMENTED`, `VALIDATED`, `DONE`, `FAILED`, `BLOCKED`
- `QUEUE_STATUS`: `QUEUED`, `ACTIVE`, `IMPLEMENTING`, `VALIDATING`, `DONE`, `FAILED`, `BLOCKED`
- Acceptance criteria: `PASS`, `FAIL`, `UNKNOWN`

Never instruct an agent to report `DONE` unless every acceptance criterion is
`PASS`. `UNKNOWN` must prevent `DONE`. `NEXT_QUEUE_ACTION` is `CONTINUE` only
when Auto Next is enabled and all criteria pass; otherwise it is `STOP`.

### Updating Webview UI

Update:

```txt
prompt-manager/src/ui/PromptManagerHtmlRenderer.ts
```

Prefer:

- Compact layouts
- Inline editing
- Drag/drop
- Collapsible sections
- Lightweight interactions

Avoid:

- Modal-heavy flows
- Giant forms
- Excessive nesting

## Important Files

### prompt-manager/package.json

Controls:

- Sidebar registration
- Activation
- Commands
- Extension metadata
- Packaging behavior

Be careful when modifying IDs.

### prompt-manager/media/

Contains extension icons and assets.

Missing media files can break VSIX packaging.

### prompt-manager/dist/

Compiled output generated by esbuild.

Should not be edited manually.

### prompt-manager/esbuild.js

Controls extension bundling/build pipeline.

## Definition of Done

Before considering work complete, run:

```bash
cd prompt-manager
npm run compile
vsce package
```

Then manually verify:

- Extension activates
- Sidebar appears
- Tasks work
- Prompts work
- Queue works
- Persistence survives reload
- Drag/drop still works
- VSIX installs correctly
- No missing assets
- No TypeScript errors
- No lint errors

## Persistence Safety

Never casually break saved workspace data.

If changing snapshot structure:

- Preserve compatibility
- Or add migration handling

PromptManager persists in three places:

- `context.workspaceState`
- `root/.promptmanager/tasks.json` and `root/.promptmanager/queue.json`
- Exported single-file JSON snapshots

All three formats should remain loadable when possible.

## UX Priorities

PromptManager should feel like:

- An AI workflow dashboard
- A queue orchestration tool
- A lightweight node/workflow system

Not:

- A plain tree view
- A simple markdown editor
- A basic prompt list
